# D5.0.3 — Pro Access Testing & UX Copy Cleanup

## 1. Overview & Context

In Ivently D5.0.2, the Pro entitlement foundation and organizer broadcast controls were hardened to enforce commercial limits (30 marketing broadcasts/month for Pro organizations, 0 for Free organizations). Free organizations retain unlimited event creation, RSVPs, audience interest, and automated transactional notifications.

During production testing on `https://ivently.up.railway.app`, an issue was identified:
- An administrator viewing an organization saw Pro capabilities marked as unavailable ("Доступно в тарифе Pro"), with no straightforward path to test Pro broadcast workflows.
- Marketing copy contained unsupported claims ("Open rate 40–60%", "приоритетная поддержка").

This release (D5.0.3) provides explicit admin testing controls, cleanses the marketing copy to reflect only verified product facts, and ensures proper public domain resolution for Railway production.

---

## 2. Root Cause Analysis

### Organization-Scoped vs. User-Scoped Entitlements
1. **Admin Role (`User.is_admin`)**:
   - RBAC flag evaluated from `settings.ADMIN_USER_IDS` via `require_admin`.
   - Grants permissions for moderation, event publishing, cancellation, and system inspection.
   - Does **not** automatically grant commercial business entitlements to every organization owned by the admin, preserving real-world multi-tenant entitlement boundaries.
2. **Commercial Plan (`OrganizationPlan`)**:
   - Strictly scoped to `(organization_id, plan, status)`.
   - Default for newly created organizations is `plan='free'`.
   - The admin was operating under an organization that had no active Pro plan assigned.
3. **Absence of UI Testing Controls**:
   - Although the backend endpoint `POST /api/v1/admin/organizations/{org_id}/plan` existed, it was not surfaced in the frontend UI, making it impossible for an admin to toggle Pro without external API calls.

---

## 3. Implemented Solution

### 3.1 Backend Admin Inspection & Testing Endpoints
- **`GET /api/v1/admin/organizations`**:
  - Lists all active organizations with their plan (`free` / `pro`), plan status, owner user ID, city, and category.
  - Requires admin credentials (`require_admin`).
- **`POST /api/v1/admin/organizations/{org_id}/plan`**:
  - Switches an organization's plan (`free` <-> `pro`) and returns updated entitlements and quota.
  - Hardened with 404 validation for nonexistent or deleted organizations.
  - Requires admin credentials (`require_admin`).
- **`GET /api/v1/admin/organizations/{org_id}/entitlements`**:
  - Inspects entitlements for any organization without ownership restriction.
  - Hardened with 404 validation.
- **Entitlement Isolation**:
  - Non-admins attempting to access any admin endpoints receive `403 Forbidden`.
  - Non-owners attempting to access `/api/v1/organizer/entitlements?org_id=...` receive `403 Forbidden`.
  - Manual creation of `broadcast_type="transactional"` via organizer API is rejected with `400 Bad Request`.

### 3.2 Frontend UI Enhancements
1. **Admin Tab (`AdminTab.tsx`)**:
   - Added section switcher: **Модерация событий** vs. **Организации и Pro**.
   - Under **Организации и Pro**:
     - Live search across organization names, slugs, categories, and cities.
     - Visual badge indicating `PRO` or `FREE`.
     - One-click testing toggle: `[ Включить Pro (тест) ]` / `[ Вернуть Free ]`.
     - Displays owner user ID for debugging.
2. **Organizer Workspace (`OrganizerWorkspace.tsx`)**:
   - Passed `isAdmin={isAdmin}` from `App.tsx`.
   - Overview Tab: Added inline admin toggle within the Pro Card to allow switching the current organization's plan on the spot.
   - Broadcasts Tab:
     - When viewing a Free organization as admin: displays `[ Включить Pro ]` admin banner.
     - When viewing a Pro organization as admin: displays `(тест: вернуть Free)` shortcut.
     - Empty state when admin has no organizations clearly prompts organization creation first.
3. **Copy Hardening**:
   - Removed: `"Высокая открываемость: Open rate рассылок в Telegram достигает 40–60%."`
   - Removed: `"приоритетная поддержка"`.
   - Factual copy preserved:
     - Direct Telegram announcements to subscribers (up to 30/month).
     - Targeting interested guests ("Хочу пойти").
     - Click and RSVP statistics.
     - Upcoming capabilities explicitly labeled `(скоро)`: auto-reminders and audience segments.

### 3.3 Production Configuration
- Added `APP_PUBLIC_HOST` configuration in `Settings` and `effective_public_host`.
- Fallback in `production` environment defaults to `https://ivently.up.railway.app`.
- Ensures image cover URLs and Telegram webhook endpoints resolve without `None` or legacy placeholder domains.

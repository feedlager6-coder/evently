## 2. Детальная спецификация информационных потоков

### Поток 1: Авторизация и вход через Telegram
* **Маршрут**: Пользователь → Telegram Mini App → Ivently Frontend → Ivently Backend (`/users/me`).
* **Категории данных**: `telegram_id`, `username`, `first_name`, `last_name`, `photo_url`, `auth_date`, `hash`.
* **Цель**: Криптографическая проверка подлинности пользователя через HMAC-SHA256 (без паролей), создание или обновление записи в таблице `users`.
* **Место хранения**: Оперативная память backend, запись в PostgreSQL на Railway.
* **Передача третьему лицу**: Нет (данные поступают от Telegram в Ivently).
* **Трансграничная передача**: **Да** (пользователь из РФ отправляет запрос на сервер Railway, расположенный за пределами РФ — в дата-центре США или ЕС).

---

### Поток 2: Использование сервиса (RSVP, Интерес, Подписки, Поиск компании)
* **Маршрут**: Frontend → Backend → PostgreSQL.
* **Категории данных**:
  - `user_id`, `event_id` (при нажатии «Я иду» или «Хочу пойти»);
  - `user_id`, `organization_id` (при подписке на организацию);
  - `user_id`, `event_id`, `note` (при создании публичной заявки на поиск компании «Ищу компанию»).
* **Цель**: Предоставление основного функционала сервиса Ivently (сохранение планов, подписок, поиск компаньонов на мероприятия).
* **Место хранения**: PostgreSQL на Railway.
* **Передача третьему лицу**:
  - Данные «Ищу компанию» (`first_name`, `avatar_url`, `note`) отображаются другим авторизованным пользователям этого же мероприятия (ст. 10.1 152-ФЗ — данные, разрешенные для распространения).
  - Списки подписчиков организаций и списки идущих на мероприятие организаторам передаются **только в агрегированном анонимном виде** (например, «42 подписчика»).
* **Трансграничная передача**: **Да** (запись в БД за пределами РФ).

---

### Поток 3: Оплата тарифа Ivently Pro (YooKassa Hosted Checkout)
* **Маршрут**: Organizer Workspace → Backend (`POST /api/v1/organizer/payments/pro`) → ЮKassa API (`POST /v3/payments`) → Hosted Checkout (ЮKassa) → Webhook (`POST /api/v1/payments/webhook/yookassa`).
* **Категории данных**:
  - Передаваемые в ЮKassa: `amount` (499.00 RUB), `currency` (`RUB`), `description`, `customer_email` (опционально, для чека), `return_url`, метаданные (`order_id`, `organization_id`).
  - Данные банковских карт: вводятся пользователем **непосредственно на защищенной платежной странице ЮKassa**. Сервер Ivently карты не видит и не сохраняет.
  - Получаемые от ЮKassa в Webhook: `event`, `object.id` (provider payment id), `object.status`, `object.amount`, `object.paid`.
* **Цель**: Оплата доступа к тарифу Pro, фискализация чека плательщика НПД в «Мой налог».
* **Место хранения**:
  - В Ivently: `payment_orders`, `payment_transactions`, `payment_webhook_logs` в PostgreSQL на Railway.
  - В ЮKassa: серверная инфраструктура ООО НКО «ЮМани» (Российская Федерация).
* **Передача третьему лицу**: **Да** (передача ЮKassa как платежному провайдеру по поручению оператора для проведения расчета).
* **Трансграничная передача**:
  - ЮKassa находится на территории РФ.
  - Запросы к API ЮKassa инициируются с бэкенда Ivently (Railway, США/ЕС) в адрес российских серверов ЮKassa (`api.yookassa.ru`), а вебхуки поступают из РФ в США/ЕС.

---

### Поток 4: Доставка транзакционных и маркетинговых уведомлений
* **Маршрут**: Ivently Backend → Telegram Bot API (`https://api.telegram.org/bot<token>/sendMessage` или `/sendPhoto`).
* **Категории данных**: `chat_id` (Telegram User ID получателя), текст сообщения (название мероприятия, дата, адрес, ссылка на чек), URL обложки мероприятия.
* **Цель**: Информирование участников об изменениях в мероприятии (транзакционные сообщения), доставка чека об оплате Pro, маркетинговые рассылки от организаций подписчикам.
* **Место хранения**: Сервера Telegram FZ-LLC / Telegram Group Inc. (ОАЭ / ЕС).
* **Передача третьему лицу**: **Да** (передача Telegram для доставки конечному получателю).
* **Трансграничная передача**: **Да** (сервера Telegram Bot API расположены за пределами РФ).

---

### Поток 5: Загрузка медиафайлов (обложки событий, логотипы организаций)
* **Маршрут**: Frontend → Backend (`POST /api/v1/media/upload`) → Railway Persistent Volume (`/app/uploads`).
* **Категории данных**: Файлы изображений (JPEG, PNG, WEBP), метаданные файла.
* **Цель**: Визуальное оформление афиши мероприятий.
* **Место хранения**: Диск контейнера Railway Volume (США / ЕС).
* **Передача третьему лицу**: Нет (файлы раздаются публично через веб-сервер Ivently).
* **Трансграничная передача**: **Да**.

---

### Поток 6: Геокодирование адресов (OpenStreetMap Nominatim)
* **Маршрут**: Frontend → Backend (`GET /api/v1/locations/suggest`) → OpenStreetMap Nominatim API (`https://nominatim.openstreetmap.org/search`).
* **Категории данных**: Текстовая строка поискового запроса адреса (например, «ул. Ленина, Махачкала»).
* **Персональные данные**: **Отсутствуют**. Поток содержит только общедоступные географические адреса объектов.
* **Передача третьему лицу / трансграничная передача ПДн**: Не применима (ПДн не передаются).

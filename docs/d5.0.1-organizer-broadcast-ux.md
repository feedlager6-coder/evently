# D5.0.1 — Organizer Messaging & Broadcast UX Audit

## 1. Overview & Context

Sprint **D5.0.1** is a targeted UX clarity and copy audit following the **D5.0 Pro Foundation & Entitlement Engine**.

The primary objective is to make the organizer workspace speak **plain, professional Russian** instead of technical developer jargon, while ensuring complete transparency regarding the Free monthly quota (3 marketing broadcasts/month), transactional event update exemptions, and the upcoming Pro value proposition — without implementing payments, fake checkout forms, or vanity metrics.

---

## 2. Free Limits Clarity & Operational Exemptions

### 2.1 Marketing Broadcasts vs. Operational Event Updates

| Message Category | Technical Identifier | Quota Impact | Fatigue Rule (24h) | Primary Purpose |
| :--- | :--- | :--- | :--- | :--- |
| **📣 Анонс** | `broadcast_type = 'marketing'` | **Consumes monthly Free quota** (3 / month) | **Enforced** (max 1 message per user per 24 hours) | Anouncement of upcoming events, program reveals, general organization news |
| **🔔 Изменение события** | `broadcast_type = 'transactional'` | **EXEMPT from monthly quota** (unlimited) | **Bypassed** (delivered immediately to all relevant attendees) | Urgent schedule shifts, venue changes, cancellations, attendee safety notices |

### 2.2 Transparent Quota Communication
In the Organizer Workspace:
1. **Overview Tab**: Displays the exact monthly count:  
   `Анонсов в этом месяце: X из 3` (with a button to learn about Pro).
2. **Broadcasts Tab Status Banner**: A dedicated indicator right below the header:  
   `Бесплатные анонсы в этом месяце: X из 3 использовано (осталось Y)`  
   accompanied by the explicit note:  
   *«Сервисные сообщения об изменениях событий не расходуют этот лимит»*.
3. **Quota Exceeded State**: When all 3 Free marketing announcements have been used, attempts to create another marketing announcement trigger an informative banner with an action button:  
   `[ ✨ Узнать о возможностях Pro ]`.

## 6. Research: Telegram Message Formatting Capabilities

### 6.1 Safe HTML Tags Supported by Telegram Bot API 7.0+
Telegram Bot API supports a specific subset of HTML tags in `sendMessage`:
- `<b>bold</b>`, `<strong>bold</strong>`
- `<i>italic</i>`, `<em>italic</em>`
- `<u>underline</u>`
- `<s>strikethrough</s>`, `<strike>strikethrough</strike>`, `<del>strikethrough</del>`
- `<code>inline fixed-width code</code>`
- `<pre>pre-formatted block</pre>`
- `<blockquote>expandable or standard blockquote</blockquote>` (API 7.3+)
- `<a href="https://...">hyperlink</a>`

### 6.2 Security & Delivery Safety
1. **Current Security Posture**: In `broadcast_service.py`, `format_broadcast_content` runs `html.escape(custom_text)`. This is essential to prevent user-supplied inputs from breaking the Telegram HTML parser (which otherwise causes Telegram to return `400 Bad Request: can't parse entities`).
2. **Future Pro Candidate ("Telegram Formatting Editor")**:
   - Rather than exposing raw arbitrary HTML input (which risks parse errors and malformed message drops), future Pro can provide a controlled WYSIWYG button bar: **Bold**, *Italic*, Quote, Link.
   - The frontend serializes styled tokens or runs an AST sanitizer that strictly whitelist-validates tags before submission to the backend.
   - Documented as an approved roadmap candidate for Pro without cluttering Free.

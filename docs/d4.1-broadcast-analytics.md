# Ivently — Sprint D4.1: Broadcast Analytics & Attribution Engine

## 1. Overview & Strategic Purpose

Sprint **D4.1** completes the feedback loop of the Ivently broadcast system. While Sprint D4.0 built the delivery engine, D4.1 provides organizers with objective attribution analytics answering the core value question:

> **«Сколько людей перешло и записалось на событие благодаря моей рассылке?»**

Attribution tracking connects Telegram message delivery to actual user engagement inside the Mini App:
$$\text{Рассылка отправлена} \longrightarrow \text{Доставлено} \longrightarrow \text{Переходы (Event Opens)} \longrightarrow \text{Хочу пойти (Interest)} \longrightarrow \text{Я иду (RSVP)}$$

---

## 2. Token Scheme & Telegram Deep Link Compliance

Telegram Mini App direct links pass startup parameters via `?startapp=<param>`. Telegram enforces a strict **64-character limit** on this parameter.

### Token Specification
- Format: `event_{event_id}_b_{attribution_token}`
- `event_`: 6 characters
- `event_id`: 36 characters (UUID v4)
- `_b_`: 3 characters
- `attribution_token`: 16 characters (hex-encoded 64-bit cryptographic entropy generated via `secrets.token_hex(8)`)
- **Total length: 61 characters** ($\le 64$ characters limit).

### Security & Privacy Properties
- **Zero user identifiers exposed**: The token identifies the broadcast campaign, NOT the recipient user. It cannot be used to trace or enumerate user identities.
- **Unguessable**: $2^{64} \approx 1.84 \times 10^{19}$ combinations, preventing parameter tampering.
- **Graceful degradation**: If the token is stripped or malformed, the parser in `App.tsx` falls back to extracting the clean `event_id`, ensuring the event always opens smoothly without user disruption.

## 3. Attribution Model & Strict Rules

To ensure 100% data integrity with zero false attribution:

### 1. 24-Hour Attribution Window
- Controlled by `Settings.BROADCAST_ATTRIBUTION_HOURS = 24`.
- Opens and conversions are only credited if they occur within 24 hours of `broadcast.created_at`.
- Actions beyond 24 hours are treated as organic visits.

### 2. Strict Event Isolation
- Broadcast for **Event A** can **only** attribute actions for **Event A**.
- If a user opens a broadcast for Event A and subsequently browses or RSVPs to Event B, Event B is never falsely attributed.

### 3. Recipient Membership Verification
- An event view is only attributed if the viewing authenticated user exists as a `BroadcastRecipient` for that broadcast.
- Third parties who receive a forwarded link or browse directly are never counted as broadcast opens.

### 4. Intent Pre-existence Exclusion
- If a user already had registered interest (`EventInterest.created_at < broadcast.created_at`) or confirmed RSVP (`EventAttendee.created_at < broadcast.created_at`) prior to broadcast creation, subsequent actions are considered pre-existing and are **not** credited as broadcast conversions.

### 5. Organic Feed & Afisha Isolation
- Normal views from discovery (`source: "discovery"`) or direct navigation without tokens carry zero attribution (`opened_count = 0`).

---

## 4. Resilience & Non-blocking Guarantee

Analytics logging is strictly non-critical path:
1. **Frontend**: Background fire-and-forget call (`api.trackEventView(eventId, 'broadcast', token).catch(...)`).
2. **Backend**: All attribution logging in `record_event_view`, `add_event_interest`, and `add_event_rsvp` is wrapped in isolated `try/except` blocks.
3. Any database exception, cache miss, or token error will log a warning and return gracefully, ensuring core user actions (opening event, RSVP, interest) **always succeed**.

---

## 5. Organizer Workspace & Privacy

### Aggregate-Only Metrics
Organizers see aggregate conversion figures:
- **Переходы (Opens)**: Total unique recipients who opened the event via the broadcast link.
- **Хочу пойти (Interest)**: Total recipients whose interest was converted via the broadcast.
- **Я иду (RSVP)**: Total recipients who confirmed attendance through the broadcast.
- **Conversion Rates (%)**: Computed relative to delivered recipients (`delivered_count`).
  - Zero-denominator protection: If `delivered_count == 0`, rates safely return `0.0%`.

### Privacy Invariant
- **No recipient lists**: Organizers never see individual recipient user IDs, usernames, or contact details.
- Responses strictly conform to aggregate schemas (`BroadcastItem`, `BroadcastDetail`).

# Ivently — D5.0.2 Pro-only Broadcasts & Transactional Notifications

## 1. Product Model & Entitlements

In D5.0.2, Ivently introduces a clear separation between **marketing audience engagement** (a premium monetization driver) and **essential event operational notifications** (a platform reliability feature):

| Feature / Capability | Free Plan | Pro Plan |
| :--- | :--- | :--- |
| **Manual Marketing Broadcasts** | **0 / month** (`FREE_BROADCASTS_PER_MONTH = 0`) | **30 / month** (`PRO_BROADCASTS_PER_MONTH = 30`) |
| **Broadcast Target Audiences** | None (Gate Card CTA) | Subscribers (`organization_subscribers`), Interested (`event_interest`) |
| **Broadcast Composer Templates** | None (Locked) | 📣 **Анонс события** (`event_announcement`), 📰 **Новость организации** (`custom_update`) |
| **Automatic Event Notifications** | **Unlimited & Free** (System-dispatched on changes/cancellations) | **Unlimited & Free** (System-dispatched on changes/cancellations) |
| **Event Creation & Management** | Unlimited | Unlimited |
| **Public Profile & Followers** | Full access | Full access |
| **Basic Analytics (Views, RSVP)** | Full access | Full access |
| **Attribution Tracking (`mb_`)** | N/A | Full access (Open rate, Interest %, RSVP %) |

Attempting to preview or create a manual broadcast under the Free plan returns:
- **HTTP 403 Forbidden**
- `{"code": "ENTITLEMENT_REQUIRED", "detail": "Рассылки аудитории доступны только в тарифе Pro", "capability": "broadcasts_extended", "required_plan": "pro"}`

## 2. Anti-Abuse Protection

To protect users against notification spam and maintain high engagement quality, manual transactional broadcasts are strictly prohibited:

- **API Enforcement**: Any manual broadcast preview (`POST /api/v1/organizer/broadcasts/preview`) or creation (`POST /api/v1/organizer/broadcasts`) specifying `broadcast_type == 'transactional'` is rejected with **HTTP 400 Bad Request**.
- **Reasoning**: Organizers cannot re-classify promotional messages as transactional to bypass marketing quota or the 24-hour anti-fatigue cooldown window.
- **UI Guardrail**: The "Изменение события" option has been permanently removed from the manual Broadcast Composer. Organizers are informed that event change notifications are dispatched automatically whenever event details change.

## 3. Automated Transactional Notifications

When critical event details change or an event is cancelled, Ivently's backend automatically dispatches transactional notifications to registered attendees and interested users:

### Trigger Points:
1. **Event Details Updated** (`PATCH /api/v1/events/{event_id}`):
   - Triggers when `start_at` changes (rescheduled date/time).
   - Triggers when `venue_name` or `address` changes (relocated venue).
   - Summarizes old vs. new values in human-readable Russian (e.g. `🕒 Дата: 12.10.2026 19:00 → 13.10.2026 20:00`).
2. **Event Cancelled** (`DELETE /api/v1/events/{event_id}` or Admin Moderation Rejection):
   - Notifies all registered attendees and interested users that the event will no longer take place.

### Technical Characteristics:
- **Zero Marketing Quota Impact**: Does not consume the organizer's monthly broadcast quota.
- **Fatigue Exemption**: Bypasses the 24-hour marketing fatigue filter to ensure critical operational updates reach users immediately.
- **Clean Deep Links**: Uses direct event navigation links (`https://t.me/<bot>?startapp=event_<event_id>`) without marketing attribution tokens (`mb_`), preventing attribution pollution.

## 4. Telegram Rich Media Delivery & Fallbacks

Telegram messages now deliver rich event visuals with seamless error resilience:

1. **Cover Photo Delivery (`sendPhoto`)**:
   - When an event has a `cover_image_url`, the notification service sends the message via `sendPhoto` with the formatted text as an HTML caption (`caption`).
   - The interactive deep link is attached as an `inline_keyboard` button (`url`).
2. **URL Resolution**:
   - Relative URLs (`/uploads/events/...` or `uploads/events/...`) are automatically normalized to absolute URLs using `APP_PUBLIC_HOST`.
3. **Resilient Fallback (`sendMessage`)**:
   - If `cover_image_url` is absent, or if Telegram returns an error (such as unreachable media, invalid dimension, or file timeout), the service automatically falls back to sending a text-only `sendMessage` with the inline button. Delivery never fails due to image issues.

## 6. Known Technical & UX Debt Note

- **"My Events → Хочу пойти" Micro-delay**: When an organizer marks interest or RSVP on their own event from the organizer view, a slight async state reconciliation delay may occur before the counter increments on the public screen. This is non-blocking and does not impact normal attendee flows. Future iterations will add optimistic counter updates on the client.

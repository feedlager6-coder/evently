# Ivently Pro Payments — Архитектура и эксплуатационная документация (D6.1)

Production URL: `https://ivently.up.railway.app`  
Платежный провайдер: **ЮKassa (YooKassa Hosted Checkout)**  
Тариф: **Ivently Pro** (499 ₽ на 30 календарных дней, разовый платеж)  
Правовой режим: **Самозанятый (НПД / 422-ФЗ), ассистированный выпуск чеков («Мой налог»)**

---

## 1. Обзор архитектуры

Интеграция построена по принципу максимальной финансовой надежности, строгой идемпотентности и защиты от дублирования списаний и продлений:

1. **YooKassa Hosted Checkout**: Платежные данные (номера карт, СБП, Mir Pay) обрабатываются исключительно на защищенной платежной форме ЮKassa (соответствие PCI DSS). Сервер Ivently никогда не прикасается к карточным данным.
2. **Единый источник правды Pro**: Статус подписки, дата окончания (`expires_at`) и лимиты определяются только в таблице `organization_plans` через `EntitlementService`. Модель `PaymentOrder` фиксирует историю заказов и статус платежа у провайдера, но не дублирует логику прав.
3. **Разовый платеж (One-Time)**: Нет рекуррентных списаний, нет автопродления (`save_payment_method: false`). При необходимости продления организатор совершает повторную осознанную оплату.
4. **Атомарное продление (+30 дней)**:
   - Если организация на тарифе `free` (или `pro` истек): `expires_at = now + 30 дней`.
   - Если организация уже имеет активный `pro`: `expires_at = current_expires_at + 30 дней` (оставшиеся дни не сгорают).
5. **Бесплатные уведомления**: Операционные и транзакционные уведомления (об изменении даты/времени/места/отмене события) остаются бесплатными и квотами маркетинговой рассылки не ограничиваются. Pro разблокирует до 20 маркетинговых рассылок подписчикам в текущем календарном месяце.

## 2. Модели данных

### `payment_orders`
* `id` (VARCHAR(36), PK, UUID): Уникальный ID заказа в Ivently.
* `organization_id` (VARCHAR(36), FK): Целевая организация.
* `user_id` (INTEGER, FK): Пользователь-инициатор (владелец).
* `amount` (FLOAT): Сумма платежа (499.00).
* `currency` (VARCHAR(3)): Валюта (`RUB`).
* `provider` (VARCHAR(30)): Провайдер (`yookassa`).
* `provider_payment_id` (VARCHAR(255), UNIQUE): ID платежа в ЮKassa.
* `idempotency_key` (VARCHAR(64), UNIQUE): Ключ идемпотентности запроса в ЮKassa.
* `status` (VARCHAR(30)): Статус заказа (`pending`, `succeeded`, `canceled`, `failed`, `refunded`).
* `service_name` (VARCHAR(255)): Наименование услуги.
* `confirmation_url` (VARCHAR(1024)): Ссылка на Hosted Checkout ЮKassa.
* `customer_email` (VARCHAR(255), NULL): Email плательщика для чека.
* `receipt_status` (VARCHAR(30)): Статус фискального чека (`pending`, `issued`).
* `receipt_url` (VARCHAR(1024), NULL): Официальный HTTPS URL чека из «Мой налог».
* `receipt_issued_at` (TIMESTAMP): Время регистрации чека.
* `pro_extended_at` (TIMESTAMP): Время активации тарифа Pro (защита от повторного продления).
* `success_notified_at` (TIMESTAMP): Время отправки Telegram-уведомления об успехе.
* `created_at` / `updated_at` / `paid_at` / `expires_at`.

### `payment_transactions`
Аудит всех переходов состояний и операций (`create_order`, `payment_succeeded`, `payment_canceled`, `refund_succeeded`). Сохраняет только безопасные метаданные (без секретов и PII).

### `payment_webhook_logs`
Журнал входящих webhook-уведомлений для защиты от повторных доставок (idempotency deduplication по `event_id` + `provider`).

## 3. Защита от дублирования и гонок (Anti-Duplicate & Idempotency)

1. **Защита от двойного клика (Duplicate Pending Reuse)**:  
   Если организатор повторно нажимает «Оплатить» при наличии уже созданного заказа в статусе `pending` (созданного менее 15 минут назад), сервер не создает второй платеж в ЮKassa, а возвращает существующий `confirmation_url`.
2. **Идемпотентность Webhook (10 deliveries = 1 activation)**:  
   При поступлении webhook `payment.succeeded` проверяется флаг `order.pro_extended_at`. Даже если ЮKassa доставит webhook 10 раз, подписка продлевается ровно один раз (+30 дней, а не +300 дней), транзакция пишется один раз, Telegram-уведомление отправляется один раз.
3. **Серверная сверка (Server-Side Reconciliation)**:  
   Когда пользователь возвращается на сайт по `return_url`, фронтенд запрашивает `GET /api/v1/organizer/payments/{order_id}`. Бэкенд напрямую опрашивает ЮKassa API (`GET /v3/payments/{id}`), проверяет `status == succeeded`, `paid == true`, точное совпадение суммы (`499.00`) и валюты (`RUB`), и только затем переводит заказ в `succeeded` и активирует Pro.
4. **Таймауты внешнего провайдера**:  
   При таймауте сетевого соединения к ЮKassa создание заказа отменяется с ошибкой 503, не оставляя битых заказов с `confirmation_url = null`.

## 4. Юридический статус и фискальные чеки (НПД / Самозанятый)

29 декабря 2025 года ЮKassa официально прекратила автоматическую фискализацию чеков через сервис «Чеки для самозанятых» для новых и существующих подключений.

В соответствии с Федеральным законом № 422-ФЗ плательщик НПД обязан сформировать чек в приложении «Мой налог» и передать его покупателю (электронно или на бумаге):
- При безналичных расчетах чек формируется не позднее 9-го числа месяца, следующего за налоговым периодом.
- Для максимальной клиентоориентированности Ivently формирует задачу администратору сразу после оплаты.

### Ассистированный флоу (Assisted Receipt Workflow):
1. Организатор при оплате указывает опциональный Email для получения чека.
2. При успешной оплате `order.receipt_status` переводится в `pending`.
3. Доступ к Pro активируется немедленно (покупатель не ждет ручной выписки чека).
4. Администратор через защищенный API видит список заказов, ожидающих чек:
   ```http
   GET /api/v1/admin/payments?receipt_status=pending
   ```
5. Администратор формирует чек в приложении «Мой налог» (ФНС) на сумму 499 ₽ с наименованием «Доступ к сервису Ivently Pro на 30 дней».
6. Администратор привязывает официальную ссылку на чек ФНС (`https://lknpd.nalog.ru/...`):
   ```http
   POST /api/v1/admin/payments/{order_id}/receipt
   Content-Type: application/json

   {
     "receipt_url": "https://lknpd.nalog.ru/api/v1/receipt/..."
   }
   ```
7. Система валидирует HTTPS URL, меняет `receipt_status` на `issued`, и отправляет организатору сообщение в Telegram с прямой кнопкой «🧾 Электронный чек».

## 5. API Эндпоинты

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| `GET` | `/api/v1/meta/payment-config` | Публичный | Получение цены (499 ₽), дней (30) и флага `payments_enabled` |
| `POST` | `/api/v1/organizer/payments/pro` | Владелец орг. | Создание заказа и получение ссылки на оплату ЮKassa |
| `GET` | `/api/v1/organizer/payments/{order_id}` | Владелец орг. | Статус платежа + автоматическая сверка с ЮKassa |
| `GET` | `/api/v1/organizer/payments` | Владелец орг. | История оплат организации |
| `POST` | `/api/v1/payments/webhook/yookassa` | Публичный (ЮKassa) | Обработка вебхуков `payment.succeeded`, `payment.canceled`, `refund.succeeded` |
| `GET` | `/api/v1/admin/payments` | Администратор | Просмотр реестра платежей и фильтрация по `receipt_status` |
| `POST` | `/api/v1/admin/payments/{order_id}/receipt` | Администратор | Привязка ссылки на чек из «Мой налог» |
| `POST` | `/api/v1/admin/payments/{order_id}/reconcile` | Администратор | Ручной запуск сверки платежа с ЮKassa |

## 6. Переменные окружения (Environment Variables)

В `backend/app/config.py` настроены параметры (значения по умолчанию безопасны для запуска без платежей):

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PAYMENTS_ENABLED` | `False` | Глобальный переключатель реальных платежей |
| `PRO_MONTHLY_PRICE_RUB` | `499.0` | Стоимость Pro на 30 дней |
| `PRO_SUBSCRIPTION_DAYS` | `30` | Количество дней доступа |
| `YOOKASSA_SHOP_ID` | `""` | Идентификатор магазина в ЮKassa |
| `YOOKASSA_SECRET_KEY` | `""` | Секретный ключ API ЮKassa |
| `YOOKASSA_RETURN_URL` | `https://ivently.up.railway.app/?payment_order_id={order_id}` | URL возврата после оплаты |

## 7. Чек-лист для владельца проекта (Запуск в продакшн)

Когда договор с ЮKassa будет оформлен или получен тестовый магазин:

1. **Регистрация в ЮKassa**:
   - Войти в личный кабинет ЮKassa (`https://yookassa.ru/my`).
   - Получить `shopId` и выпустить секретный ключ API (`secretKey`).
2. **Настройка Webhook в личном кабинете ЮKassa**:
   - Перейдите в раздел «Интеграция» -> «HTTP-уведомления».
   - Укажите URL: `https://ivently.up.railway.app/api/v1/payments/webhook/yookassa`
   - Отметьте события:
     - `payment.succeeded`
     - `payment.canceled`
     - `refund.succeeded`
3. **Добавление переменных в Railway**:
   - Откройте проект Ivently в Railway -> вкладка `Variables`.
   - Добавьте:
     - `YOOKASSA_SHOP_ID` = `<ваш_shopId>`
     - `YOOKASSA_SECRET_KEY` = `<ваш_секретный_ключ>`
     - `PAYMENTS_ENABLED` = `True`
4. **Тестовая транзакция**:
   - Создайте организацию в Ivently.
   - Откройте блок тарифа Pro -> нажмите «Перейти на Pro за 499 ₽».
   - Укажите Email и оплатите (тестовой картой или реальной на 499 ₽).
   - Убедитесь, что статус организации сменился на Pro, доступно 20 рассылок, в истории оплат заказ отображается со статусом «Оплачен», а в Telegram пришло подтверждение.
